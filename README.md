A fast web viewer for **10x Genomics Xenium** spatial transcriptomics together with the
**registered H&E** and the **morphology stains** of the same section. A Rust import step
builds a compact, disk-backed index once per section; a Rust server streams only what the
current view needs to one WebGL2 canvas (deck.gl) in the browser. Whole cohorts of large
sections (hundreds of thousands of cells, tens of millions of transcripts) stay smooth on
an ordinary workstation, and colleagues only need a browser.

**[Try the online demo](https://vinc395.github.io/novium-spatial-explorer/)**: two small
synthetic sections (generated, not biological data) in your browser, no installation.

The command-line tool and code use the working name `xenium-web`.

## What it shows

- **H&E** at native resolution, placed by an explicit image → Xenium µm transform
  (Xenium Explorer alignment file, an affine matrix, or an image already warped onto the
  Xenium grid; rotation and mirroring supported; never guessed or warped)
- **Morphology stains** (DAPI, ATP1A1/CD45/E-Cadherin, 18S, alphaSMA/Vimentin…) on the
  Xenium pixel grid, each with its own colour, brightness and opacity, mixed additively
- **Cells and nuclei**: outlines, fills or dots, with the original `cell_id`s
- **Colour by anything per cell**: Xenium columns, your annotations (any number of
  categories), precomputed scores such as ligand–receptor results, gene expression
  (QV ≥ 20 counts), or gene-signature scores computed in the viewer (UCell, identical to
  R UCell 2.14), with an **overlay** to show a second field on top
- **Transcripts**: gene search, multi-gene colours, QV filter; exact points when zoomed
  in, density when zoomed out
- **Niche grids** and other segmentation-free maps as their own layer
- **Legends** to show or hide categories, choose a colour scheme, shuffle or pick each
  category's colour, and grey out or hide cells without a value
- **Up to four sections side by side** with linked zoom and shared colours
- **Cell inspector, lasso selection and CSV export** with original IDs
- **Figure export**: the panel windows as PNG, JPEG, TIFF or PDF at up to 4× screen
  resolution and a chosen DPI, with the legend as a separate, editable SVG
- **Registration QC** that measures H&E (or DAPI) alignment against the Xenium nuclei
- **Sharing**: HTTPS with a private link or password on your network, or a per-person
  sign-in behind an optional Cloudflare tunnel

## Quick start (synthetic data)

Requirements: Rust (stable), Node.js ≥ 20, and a browser with WebGL2.

```bash
cargo build --release -p xenium-cli            # -> target/release/xenium-web
(cd web && npm ci && npm run build)            # -> web/dist

B=target/release/xenium-web
$B synth --out demo --morphology               # a small artificial section (not biological data)
$B ingest --section-id DEMO --xenium demo/xenium --index-root index \
  --he demo/he.tif --he-registration demo/registration.json \
  --morphology demo/xenium/morphology_focus \
  --annotations demo/cell_annotations.csv --lr-scores demo/lr_cell_scores.csv \
  --grid niches=demo/niche_grid.csv
$B serve --index-root index --static-dir web/dist     # open http://127.0.0.1:8080
```

## Your own data

**[docs/INPUTS.md](docs/INPUTS.md)** walks through every input: the Xenium output (cells,
boundaries, transcripts), the H&E and its registration, the morphology stains, per-cell
annotations, scores (including ligand–receptor results and large column bundles), niche
grids and per-sample information. The precise formats are in
[docs/DATA_CONTRACT.md](docs/DATA_CONTRACT.md).

In short:

```bash
xenium-web inspect --xenium /path/to/outs            # what is there (schemas and counts only)
xenium-web ingest --section-id S1 --xenium /path/to/outs --index-root /data/index \
  --he he.ome.tif --he-alignment-csv he_imagealignment.csv \
  --morphology /path/to/outs/morphology_focus --annotations cell_types.csv
xenium-web qc-registration --index /data/index/S1    # is the H&E aligned?
xenium-web serve --index-root /data/index --static-dir web/dist
```

No data are included in this repository. Everything in the tests is generated by
`xenium-web synth`.

## Sharing and deployment

The server binds `127.0.0.1` by default (use an SSH tunnel to view it remotely).
[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) covers HTTPS on a local network with a private
link or password, an always-on systemd service, per-person sign-in, an optional public
address through Cloudflare, ingest on an HPC cluster, and a security checklist. Check that
sharing your data is covered by your ethics and data-management approvals.

## How it works

[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) describes the design and
[docs/API_SPEC.md](docs/API_SPEC.md) the HTTP API.

```
crates/xenium-core    frames, affine transforms, registration, cell-ID dictionary, binary codecs, manifest
crates/xenium-io      Parquet/CSV/TIFF readers, experiment.xenium, synthetic data generator
crates/xenium-index   ingest (external sort), image pyramids, packed storage, atomic publish, validator
crates/xenium-score   UCell gene-signature scoring (bit-identical to R UCell 2.14)
crates/xenium-server  Axum HTTP API, sign-in, static web UI
crates/xenium-cli     the `xenium-web` command: synth, inspect, ingest, validate, qc-registration, ucell, serve, users, certificates
web/                  React + deck.gl single-canvas viewer
deploy/cloudflare     optional Cloudflare Worker for a fixed public address
scripts/              verification, LAN serving, systemd service, Cloudflare tunnel, Slurm template, converters
```

## Development

The online demo is built with `scripts/build_demo_site.sh` (synthetic data only) and
checked with `cd web && npx playwright test -c playwright.demo.config.ts`; see
[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md#online-demo-github-pages).

`scripts/verify.sh` runs every check: `cargo fmt --check`, clippy with `-D warnings`, the
Rust tests, TypeScript type checks, vitest, the web build, a synthetic ingest and
validation, an HTTP smoke test and the Playwright browser tests (install the browser once
with `cd web && npx playwright install chromium`). The UCell parity tests compare against
stored R results; with `scripts/setup_ucell_reference.sh` they also run live against R.
